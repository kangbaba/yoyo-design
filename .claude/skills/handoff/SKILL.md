# Handoff Skill

When the user invokes `/handoff`, generate a `HANDOFF.md` file in the project root for handing off the current task to another AI agent.

## Steps

1. **Archive previous handoff** (if `HANDOFF.md` exists):
   - Count existing files in `handoff_history/` to determine the next sequence number
   - Copy current `HANDOFF.md` to `handoff_history/{seq}_{source_agent}.md`
   - Source agent is `claude` (since this handoff is generated by Claude Code)

2. **Generate new `HANDOFF.md`** with the following structure:

```markdown
# Task Handoff

**Generated by:** Claude Code
**Timestamp:** {YYYY-MM-DD HH:mm:ss}
**Project:** {project directory name}

## Current Task
{One paragraph describing the overall goal and what we're building}

## Completed Steps
- [x] {step 1 - what was done}
- [x] {step 2 - what was done}

## Remaining Steps
- [ ] {step 1 - what needs to be done}
- [ ] {step 2 - what needs to be done}

## Key Decisions
- {decision}: {reason}

## Modified Files
- {path/to/file} - {what was changed and why}

## Current State
{Any blockers, open questions, in-progress work, or important context the next agent needs}

## Instructions for Next Agent
Follow `AGENTS.md` in the project root for all workflow rules.
Follow `CLAUDE.md` for design specs and exact values.
```

3. **Report to user**: Tell the user the handoff file is ready and show the path. Remind them to run Codex with something like:
   ```
   codex "Read HANDOFF.md and continue the task. Follow AGENTS.md and CLAUDE.md for guidelines."
   ```

## Rules

- Fill every section based on actual conversation context. Do NOT leave placeholders.
- If a section has no content (e.g. no key decisions), write "None" instead of omitting it.
- Keep descriptions concise but specific enough for a cold-start agent to understand.
- Include file paths, not just descriptions.
- The `Remaining Steps` section is the most critical - be thorough.
